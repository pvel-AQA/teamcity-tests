Coverage gaps

Page objects no test reaches. Each is either an untested area of the product or dead code that should be deleted.

  • BuildConfigurationPage — declares /buildConfiguration/%s
  • EditBuildStepsPage — declares /admin/editBuildRunners.html?id=buildType:%s

Never used directly, but subclassed. These behave as base classes: no test names them, yet their route and behaviour are exercised through a subclass. Not a coverage gap — but if a class is only ever a base, it belongs in the hierarchy as abstract, which would take it out of this denominator.

  • EditBuildHeaderPage — extended by EditBuildGeneralPage, EditBuildStepsPage, EditBuildTypeVcsRootsPage

Page objects with an empty url(). These cannot be opened directly, so they are only ever reachable through another page. Giving them a real route makes them independently testable and shrinks setup time.

What this number is not. Reaching a page is not the same as testing it — a page can be opened with no assertion made against it. Route coverage is a floor, not a quality measure: it tells you where the suite has never been, which is reliable, and says nothing about the depth of what it does when it gets there. Pair it with the declared feature inventory for a number worth reporting.
